Settings
Game Mode
Sets the ruleset context for the sheet. BattleTech Classic — using BV (Battle Value).
Force Options
When checked, BSP is set to 0 and BV Available is increased by 500 per scale (500 / 1,000 / 1,500 / 2,000 / 2,500 / 3,000).
When checked, exposes a Number of Jumps field on the Contract tab. Travel cost becomes 50 + (50 × Jumps) instead of the flat 300 per scale.
When checked, non-named pilots count as a 0 handicap for Handicap averaging if the piloted unit is at least 500 BV.
When checked, ledger entries from Send to Ledger include full details — expense type, unit or pilot name — instead of just the section title.
× base repair cost
Applied to Repair Costs on the Support Costs tab when a unit's Tech Base is set to Clan or Mixed. Default is 1.5×. This is a house rule — not an official BattleTech rule.
Data is automatically saved to your browser's local storage. Use Save All Data to manually force a save. Clear All Data will permanently erase everything.
Export & Import
Export your contract data as a JSON file to back it up or transfer it. Import a previously exported file to restore your data.
GitHub Gist Sync
Sync your data to a private GitHub Gist so it's accessible across browsers and devices. Requires a GitHub Personal Access Token with gist scope.
Generate one at github.com → Settings → Developer settings → Personal access tokens (fine-grained: enable Gists read+write; or classic: enable gist scope).
If you see "Bad credentials": your token may have expired, or was created without the Gist scope. Generate a new one — fine-grained tokens expire by default.
Security Note
Your token is stored in localStorage on this device only and is never transmitted anywhere except directly to api.github.com. Use a fine-grained token scoped only to Gists to minimise risk. Revoke it from GitHub at any time.
Import Force from CSV
Upload a MekBay-style CSV file to populate formations on the Force Record tab. Each row becomes a unit entry.
Supported columns (case-insensitive): unit, tons, bv, status, omni, techbase, formation
The formation column is optional — if present, rows are grouped by its value into separate formations. If absent, all rows go into one formation.
